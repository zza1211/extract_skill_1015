# 本地抽取与经验工作台（0.5.0）

工作台读取 OpenCode 使用的同一私有库，展示抽取任务、经验变化、验证结果和待确认问题。普通浏览不调用模型；在“抽取与学习”明确启动任务后，会通过本机 OpenCode 执行模型调用。整体技术与数据流见[演进方案](learning-evolution.md)。

## 启动与打开

在仓库根目录运行，需要 Python 3.10+，不需要 Web 框架或前端依赖：

```powershell
python -X utf8 .opencode/skills/term-extract/scripts/memory_ui.py
```

打开终端显示的本机地址，默认 `http://127.0.0.1:8765/`。保持终端运行，停止服务按 Ctrl+C。更换端口或只读查看：

```powershell
python -X utf8 .opencode/skills/term-extract/scripts/memory_ui.py --port 8766
python -X utf8 .opencode/skills/term-extract/scripts/memory_ui.py --read-only
```

从其他目录启动可传 `--project-root 'D:\你的目录\extract_skill_1015'`。默认私有库为项目的 `.term-memory/`；如果 OpenCode 设置 `TERM_EXTRACT_MEMORY_DIR`，页面终端也要使用同一设置。页面显示项目与存储位置。

服务只监听本机回环地址，无账号系统。审核人姓名是审计信息，不是身份认证。HTTP 写接口检查请求来源和会话令牌；只读模式禁止创建、启动和其他写操作。GET 查询本身不写库，可写服务的后台维护可能保存扫描记录。

## 六个入口

| 入口 | 用途 |
|---|---|
| 抽取与学习 | 新建两种模式任务、选择模型与预算、导入可信案例、查看执行结果和实验 |
| 待确认事项 | 回答局部语义差异和疑似经验冲突，查看已答复记录 |
| 经验库 | 阅读规则、适用范围、来源、修订和当前生效版本 |
| 运行与反馈 | 追溯原有不可变运行、用户原话、修正稿和证据 |
| 固定业务口径 | 阅读当前业务规则和真实 Git 历史差异 |
| 更新历史 | 核对原有修订、来源确认、评测、发布与撤回事件 |

任务完整过程见“抽取与学习”的任务详情；固定口径文件变更、候选保存和正式发布是不同事件，不统称“已学习”。

## 第一次使用

### 1. 设置模型和预算

进入“抽取与学习 → 模型设置”，填写本机 OpenCode 已配置的 `provider/model`，可查看可用模型。页面不保存 API 密钥；若提供商尚未连接，应先在 OpenCode 配置。

设置最多模型调用、累计执行时间、单次超时、提示字节和独立案例数量，并选择是否允许实验通过后自动发布。网页任务使用这份配置，不自动继承某个聊天窗口当前选中的模型。

### 2. 选择纯抽取或标签学习

“新建任务”中填写本机输入路径：

- **纯条款抽取**：只提供标书，留下抽取结果和原文支持的观察；没有标签不会把自检当正确答案。
- **标签学习**：再填写正确标签路径和案例族。标签需与输入同套 Cxx，且已经按当前口径确认。隔离工作器先盲抽，冻结后才对照标签。

路径指服务所在电脑上的文件，不是浏览器上传；不要填写不存在的另一台机器路径。高层工作器使用完整原文，提示或模型窗口不足时会保留错误和下一步，不会自动截断标书完成抽取。

### 3. 导入验证案例

在“可信案例 → 导入案例”提供输入、标签和案例族。选择学习案例、独立回归或保留测试。同一模板、项目变体、译文和近重复文档使用同一案例族。

需要至少两个与候选归纳来源不同的独立案例族，才能组织回归和反例。系统还会检查反例是否触及候选的适用／排除边界；仅凑足数量不代表证据充分。保留测试不参与自动经验归纳和晋级。

导入可信标签不要求重复人工 `confirm-run`。标签来源约定由你确认，程序只检查结构、标签与工件一致性。

## 跑完之后看什么

任务详情按真实记录展示：抽取结果、标签比较、产生的候选、验证与发布、模型用量和执行过程。先看“下一步”和当前状态：

| 状态 | 下一步 |
|---|---|
| 需要模型配置 | 保存可用模型设置后继续任务 |
| 正在执行 | 等待并查看进度，无需重复启动 |
| 等待确认 | 进入待确认事项，只回答相关局部问题后继续任务 |
| 等待验证案例 | 导入同口径且独立的相关案例，再继续任务 |
| 预算已用完 | 已有结果保留；调整预算后继续 |
| 执行失败 | 检查错误及调用工件；修复后继续，或在输入变化时新建任务 |
| 已完成 | 核对结果与经验结论；无新经验也属于正常完成 |

继续任务会复用冻结预测和有效缓存。已完成任务若要重抽，使用新任务；源文件或业务口径变化需新建任务。生产快照保持不变，每项候选实验单独固定启动时正式集合，集合变化会重新建立该项实验基线。

“候选已保存”不等于“已生效”。实验通过但关闭自动发布时，需要维护者审阅报告后手动发布；候选验证失败则保留实验结论，不能为了消除状态而强制发布。

## 怎样回答待确认事项

每项展示问题、原文或规则上下文、可选意见和作用范围。范围差异先由局部判断处理，仍不确定的项才交给你。明确的漏产品、多产品、错误数量和错误串联不能通过选择“无害”覆盖。

你可以在网页选择并补一句理由，也可以在 OpenCode 明确回复某一 `review_id`。`term_learning_reply` 将选项、用户原话和消息引用写到同一待办；agent 不能代替你答复。处理一次即可，不存在网页和聊天两套审核状态。

答复只作用于指定案例或经验版本，不隐式确认整篇结果、批准所有候选或修改全局业务规则。已答复记录不可覆盖。回答后返回任务点击“继续任务”。

新增候选会检查冲突。可写服务运行时，后台每 60 秒检查是否需要扫描：候选或业务口径变化时重扫，否则默认七天一次；服务停止期间不执行。待确认入口的“检查经验冲突”可以立即强制扫描。维护只保存疑点与待办，不调用模型或自动修改发布集合。

禁用后台维护时启动：

```powershell
python -X utf8 .opencode/skills/term-extract/scripts/memory_ui.py --no-maintenance
```

`--read-only` 同样不启动维护。

## 经验详情与旧记录维护

### 最新候选与正式版本

例如 v1 已发布、v2 为候选，页面同时展示当前生效 v1 和最新 v2。新修订未通过验证时不影响 v1。编辑规则创建新 revision，不改写历史；并发修改会要求刷新再审阅。

旧来源维护入口仍保留确认来源、补反馈稿、创建修订、执行旧离线评测、手动发布与撤回。新可信标签任务无需逐条重复这些旧步骤。旧 manifest 路径仅用于特殊维护，日常高层学习由系统组织模型实验。

### 只有反馈原话，没有完整修正稿

原有反馈详情可以上传完整七字段 JSON 数组。工具保留旧 run 和原话，创建新的带稿反馈，旧无稿记录保留。旧流程需人工确认这个新反馈来源；它不会自动修改工作目录 final，也不会自动发布经验。

如果你已经有明确确认的整篇正确标签，也可将输入与该结果作为可信案例导入新流程。不要把 agent 尚未核验的整理稿直接当作用户正确标签。

### 手动评测与撤回

旧离线评测只检查给定输出与人工断言，不运行模型，格式见[旧回归清单](../.opencode/skills/term-extract/references/memory-evaluation.md)。新自动实验的报告有独立来源与工件门槛，两者不能混淆。

撤回移除当前发布指针，保留来源、规则、实验和审计，不自动恢复旧版。后续新任务不再固定该经验，已注册任务保留旧快照。恢复时需针对当前集合重新验证，不能重用已消费报告。

## “已经更新了什么”如何感知

- “抽取与学习”展示本次产生多少候选、尝试哪些实验及其结论。
- “待确认事项”列出仍需判断的问题，答复后保留原话。
- “经验库”展示候选正文、来源和已发布版本；修订差异可直接查看。
- “固定业务口径”展示技能文件变化，历史来自真实 Git；没有历史就明确提示。
- 更新不会立即替换正在执行任务的经验快照。下一篇新任务才能使用新发布集合，交付记录可核对具体版本。

模型收到某条经验不代表采用，发布也不代表所有文档都能召回。token 或费用缺失显示未记录，不等于零成本。

## 技术和限制

```text
浏览器 → memory_ui 本机 HTTP
    → memory_dashboard / evolution_dashboard
    → learning_runner / learning_compare / evolution_store
    → 原有 memory_store / memory_learning / SQLite 和私有工件
    → 新任务快照和关键词召回
```

页面参考 OpenViking Lite 的浏览与详情组织方式，代码为本项目实现，不复制其存储或自动生效语义。原生页面无 CDN、外部字体或前端构建步骤。列表和查看为本地运算，明确启动任务才调用模型。

证据摘录有限并提示截断，不等于完整原文。系统没有多用户认证、完整语义冲突识别或向量检索；不能自动证明全部人工标签可靠、所有案例族真正独立。合成测试通过也不代表真实标书效果已经验证。

私有数据库、文档和任务工件被 Git 忽略。推送代码不会携带这些数据。

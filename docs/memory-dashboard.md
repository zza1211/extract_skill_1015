# 本地记忆工作台

工作台让维护者直接看到“留下了什么、改变了什么、下一篇能否用到”。它读取 OpenCode 使用的同一经验库；不复制另一份记忆，不调用模型，也不修改抽取结果协议。界面参考 OpenViking Lite 的浏览和详情组织方式，代码与页面为本项目实现。

## 启动与打开

在仓库根目录运行，需要 Python 3.10+，不需要安装 Web 框架或前端依赖：

```powershell
python -X utf8 .opencode/skills/term-extract/scripts/memory_ui.py
```

默认打开地址为 `http://127.0.0.1:8765/`。保持终端运行，结束时按 Ctrl+C。更换端口：

```powershell
python -X utf8 .opencode/skills/term-extract/scripts/memory_ui.py --port 8766
```

只查看、不允许写操作：

```powershell
python -X utf8 .opencode/skills/term-extract/scripts/memory_ui.py --read-only
```

从其他目录启动可传 `--project-root 'D:\你的目录\extract_skill_1015'`。默认私有库为该项目的 `.term-memory/`；如果 OpenCode 设置了 `TERM_EXTRACT_MEMORY_DIR`，启动页面的终端也要设置为同一目录。页面会显示实际项目与存储位置，便于核对。

服务仅监听本机回环地址，请在终端显示的同一地址打开页面。页面没有账号系统，审核人姓名仅用于审计。HTTP 写接口校验请求来源和会话令牌；不需要把端口暴露给其他机器。仅浏览空库不会创建数据库。

## 四个入口分别看什么

| 入口 | 看到什么 | 回答的问题 |
|---|---|---|
| 经验库 | 规则全文、适用及排除条件、来源、修订差异、评测和发布状态 | 这条规则写了什么？为什么还没生效？ |
| 运行与反馈 | 不可变运行、抽取结果、用户原话、修正稿和原文证据摘录 | 它从哪次抽取或纠错产生？人工核验了吗？ |
| 固定业务口径 | 当前 business-rules.md、真实 Git 历史差异 | 用户补充的业务范围具体改在哪里？ |
| 更新历史 | 候选修订、反馈、来源确认、发布和撤回等事件 | 刚才究竟发生了哪一步？ |

页面不把三类变化混成一个“已学习”：保存反馈是留存事实，候选修订是改变待验证规则，发布才改变后续新任务的经验集合。固定业务口径通过技能文件维护，有自己的 Git 变更记录。

## 抽取结束后，下一步怎么做

1. 打开“运行与反馈”，核对本次运行、结果和复盘。如果结果正确，可以确认该运行作为成功来源；如果有错，先保留用户原话与完整修正稿，再确认带稿反馈。
2. 打开对应候选。直接阅读触发词、适用前提、动作与排除条件；不合理的规则暂不发布。编辑会创建新 revision，旧版和正在生效的版本都保留。
3. 按详情中的未完成事项补齐来源确认和离线评测。先在外部准备 baseline、candidate、独立回归/反例及人工断言 manifest，再在页面输入该文件在服务器本机上的路径执行评测。格式和实验流程见 [回归清单](../.opencode/skills/term-extract/references/memory-evaluation.md)。
4. 审阅可用报告与规则后，由维护者填写审核信息并发布。发布成功后，**之后新注册的任务**才能冻结并召回该版本；已注册任务保留原快照。

来源确认不是规则批准，结构校验也不是业务验收。对于已发现遗漏或错误的运行，不要为了消除“未确认”标记而确认它正确；应核验修正稿。

### 只有反馈原话，没有完整修正稿

在反馈详情中上传完整七字段 JSON 数组，不是只上传被修改的几个条款。服务复用原结构与标签校验，保留原话和旧 run，创建新的带稿反馈；旧的无稿反馈不覆盖、不删除。请确认新的反馈来源，再将候选规则引用到该来源。上传修正稿不会直接改写工作目录中的 final，也不会自动发布经验。

### 最新候选和已发布版同时存在

例如 v1 已发布，随后创建 v2 候选：页面同时显示“当前生效 v1”和“最新候选 v2”。v2 的门槛未通过不会影响 v1；切换到历史版本可以核对正文和差异。编辑提交附带所见的最新 revision，若其他维护操作先创建了新版本，会要求刷新后重新审阅，避免覆盖未看到的修改。

### 撤回与重新发布

撤回删除当前发布指针，保留规则、来源、评测和审核历史，不自动恢复更早版本。后续新任务不再固定该经验；已注册任务继续保留自己的快照。恢复时需要针对当前集合重新评测和发布，不能重用已消费的评测报告。

## “已保存但没生效”怎样排查

| 页面状态 | 含义与下一步 |
|---|---|
| 候选、来源未确认 | 先核验来源；规则还不会被生产召回 |
| 反馈缺完整修正稿 | 补全且核验完整结果，确认新产生的带稿反馈 |
| 没有可用评测 | 准备真实实验工件与 manifest，再执行评测 |
| 报告过期或已使用 | 来源、文件、代码或发布集合可能变化；重新评测 |
| 已发布 | 后续新任务可按疑点召回，不代表每篇一定命中或模型一定采用 |
| 最新版候选、旧版已发布 | 当前仍使用旧版；新候选还在验证 |
| 固定口径已改变 | 技能文件更新了；旧运行记录不自动重算，不代表所有相关候选均已修正 |

“更新历史”可以核对操作是否已经落库。刷新读取当前数据，不会重新抽取标书，也不会自动把未经确认的内容变成经验。

## 技术与数据流

```text
浏览器 HTML / CSS / JavaScript
    → memory_ui.py：本机 HTTP、静态资源、请求校验
    → memory_dashboard.py：列表、详情、差异、门槛与操作适配
    → memory_learning / memory_store / memory_evaluate
    → 原有 SQLite + 内容地址归档 + 原输入/index/评测工件
```

页面不引入向量库、embedding 或额外推理费用。列表、详情与差异在本机计算，浏览器按需读取；证据摘录有预算并提示截断，不声称摘录等于完整原文。评测和发布仍校验原文件及摘要，因此需要保留原输入、index、归档和外部评测工件。

固定口径正文从本地技能文件读取，历史差异来自 Git；没有可用历史就明确说明，不虚构旧版本。历史运行的口径摘要与当前不同只是版本提醒，不是自动语义判错或冲突检测。

读写接口调用原有函数。发布仍要求来源确认、可用内部报告、独立回归和反例保护，以及当前工件和发布集合一致；工作台不增加绕过门槛的发布方式。OpenCode 的 extractor/curator 工具权限不变，不能代替维护者调用页面接口确认或发布。

该版本没有自动生成实验输出、自动判断完整业务正确性、自动修正规则冲突或多用户权限管理。完整底层方案见 [经验记忆技术方案](memory-architecture.md)。私有库、标书和运行结果仍被 Git 忽略，推送只包含页面、服务、测试和说明。

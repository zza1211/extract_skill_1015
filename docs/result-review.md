# 标书结果校验与反馈学习（0.7.0）

OpenCode 负责抽取和总结，网页负责展示结果、保存用户修改与明确的整篇确认。每次正式提交后，Agent 都提示你到网页校验；网页不会调用模型，也不会因点击按钮在后台唤醒 OpenCode。

## 一篇标书怎样走完

1. 正常在 OpenCode 抽取并提交。Agent 给出 `run_id`、结果文件路径，并提醒校验。网页“条款校验”按输入标书分组显示运行和状态。
2. 在网页选中标书及运行，左侧看抽取条款，右侧看带缩进的原始 JSON。C 标签高亮；点击条款起始或终止标签，跳到原文对应位置。大文件按页展示，跳转会定位包含标签的原文页。
3. 修改标题、边界、数量和关联等字段；可把条款标记为非目标，或删除某条条款。每次保存都记录原值、新值、操作类型、时间和填写的原因；不是只保留最终文件。
4. 检查整篇是否还有漏设备、缺参数或混入其他设备参数，再填写校验人、文档家族，明确点击“完成整篇校验”。即使没有修改，也需要这次显式确认。
5. 回到 OpenCode 发送“校验完成，请从已校验结果学习”。Agent 读取当前已确认修订、对比原始结果和用户修改，回读原文，再总结候选经验或说明没有新经验。
6. 网页显示已学习及关联候选。候选需要独立评测通过，或人工审核发布，才会进入下一篇抽取的经验召回。

产品分类仍只作参考。人工重点检查目标设备齐全、关键选型参数完整、没有混入其他设备参数，以及数量和 general/separate 关联正确；多出少量不影响选型的说明不必为了对齐边界而反复调整。

## “保存”“完成整篇校验”和“删除本篇结果”有什么区别

| 操作／状态 | 含义 | 是否能据此学习 |
|---|---|---|
| 未校验 | 新抽取结果尚未得到整篇确认 | 不能作为可信标签学习 |
| 保存修改 | 保存局部编辑或删除，整篇仍待核查 | 不能，仅保留修改记录 |
| 校验完成、待学习 | 用户确认当前整个结果可用，包括没有修改的结果 | 可以，由 OpenCode 读取后归纳 |
| 已学习 | 本次确认修订已处理，记录了候选或无新经验原因 | 不重复生成；经验不因此自动生效 |
| 已校验后再次修改 | 产生新修订，原来的确认和学习属于旧版本 | 当前版本需重新校验 |
| 整篇弃用 | 这篇结果不再需要，按标书移出有效结果；与某条条款误抽不同 | 不生成纠错反馈，不进入待学习 |

“这条是非目标”和“删掉这条”针对具体抽取条款，保留为纠错操作。整篇弃用只表达“不再需要这份结果”，不能据此推导整篇抽错或让 Agent 学习删除所有设备。弃用保留审计和原始归档，不删除输入标书；恢复后需要重新校验当前结果。

聊天中说“校验完成”是要求 Agent 开始读取，**不能替代网页的“完成整篇校验”按钮**。网页没有确认时，Agent 会说明仍待校验，不替你点击、不填写你的名字。

## 文件怎样同步

每次运行有两份不同用途的结果：

- **原始模型预测**：提交时的不可变运行归档，保留原始七字段结果、证据、输入和索引绑定，用于追溯和盲抽评测。网页不覆盖它。
- **当前结果**：索引所在目录下 `review/<run_id>/result.json`，七字段 JSON 数组。网页修改会同步这个文件；非目标或删除的条款从当前有效结果中移出，操作历史保留其原内容。

网页显示当前结果路径，导出或业务下游应使用此路径。原先 `final/result.json` 等抽取交付文件继续代表该次模型提交，不能把人工修改结果覆盖回原预测后声称盲抽正确。

在外部直接编辑当前结果文件时，网页会显示文件变化，需要执行同步并核验结构。同步也属于新修改，原来的整篇确认失效；结构通过仅说明格式可读，仍需用户重新点击“完成整篇校验”。原始标书、索引或不可变归档缺失／漂移会阻止校验学习，不会静默接受另一份文档。

校验完成会保存一份不可变标签快照和内容哈希。Agent 导入可信案例引用这份快照，而不是继续指向可编辑文件，所以后续编辑不会把已归档的学习来源悄悄改写。界面状态、候选来源会绑定明确的 `run_id + revision + verified_sha256`。

修订与校验状态存放在私有目录 `.term-memory/document-review.sqlite3`，只追加历史；读取回执、标签揭示记录与候选经验存放在原有记忆库中。备份时应保留整个私有目录以及输入、索引和工作结果。页面浏览不创建数据，旧运行第一次保存或确认时才建立修订。

“删除本篇结果”影响同一输入内容的所有历史运行，可以从“已丢弃”筛选中恢复；恢复后需要重新校验。同一输入以后再次抽取，仍遵循整篇丢弃状态，需明确恢复。若工作文件损坏或存在未导入修改，整篇操作仅隐藏／恢复记录，保留问题文件，并在页面提示，避免覆盖外部修改。

同一确认修订的学习调用会串行处理。多个 OpenCode 会话同时总结时，先完成的一次保存结论，后续调用返回既有记录，不重复创建另一组候选；进程异常退出会自动释放学习锁。不同标书不互相占用这个锁。

## Agent 如何读取和归纳

```text
原文 + 原始预测
    ↓ 网页修改／删除／非目标，保留操作历史并同步当前结果
用户显式完成整篇校验
    ↓ 冻结标签快照；状态为“已校验待学习”
用户回到 OpenCode 要求学习
    ↓ term_review_pending：只列安全编号和状态
    ↓ term_review_read：分页读取原始结果、确认结果、用户操作
    ↓ Agent 回读有关原文，区分本篇答案和可迁移规律
    ↓ term_review_reflect：归档可信开发案例、去重生成候选或记录无新经验
状态为“已学习”
    ↓ 独立 A/B 评测，或人工审核发布
后续新抽取任务固定经验快照后按疑点召回
```

工具没有模型调用或后台编排。读取确认答案会记录“此会话已接触标签”，随后抽取新标书应开新会话，避免把人工答案带入盲抽或验证。

复盘最多三条，必须有本篇真实 C 标签，说明适用前提、判断或核验动作、排除条件和本次观察。例如，把采购数量改正后，可以总结“如何区分设备采购量与端口数量”，不能把“这篇交换机有 2 台”写成适用于下一篇的规则。不修改也可从确实值得保留的正确处理方法归纳；没有新规律时记录原因，完成学习，不机械制造经验。

## 实际使用提示

完成网页校验后，可在原 OpenCode 会话发送：

```text
我已在网页完成标书校验，请从已校验结果学习。
先列出待学习的 run_id 和修订，读取对应原始抽取、校验结果及操作，
结合原文总结可迁移经验。没有新经验也记录原因；不要直接发布候选。
```

若有多篇已确认结果，可指定 `run_id`，或明确要求处理全部待学习结果。Agent 在一篇学习完成后可以继续读取其他已确认结果；这些会话不能再用于新文档盲抽。经验评测的原始预测由全新 `term-trial` 子会话生成，不能拿网页人工结果冒充模型预测。

网页“已学习”表示确认修订已被处理，不表示产生了新规则，也不表示规则已发布。要查看生效原因，继续在经验库查看候选、来源、精确修订与发布记录。

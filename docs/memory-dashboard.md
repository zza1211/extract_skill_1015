# 本地记忆管理工作台

抽取和学习统一由 **OpenCode 的 term-extractor 代理自主编排**。网页读取同一个私有库，用来管理经验、导入可信案例、查看学习记录和答复人工待办；网页不选择模型、不创建或继续抽取，也不启动模型调用。

原 0.5.0 网页流程生成的任务仍保留在“历史流程”，仅供查阅，不再提供继续按钮。架构与数据流见[演进方案](learning-evolution.md)。

## 启动与打开

在仓库根目录运行，需要 Python 3.10+，不需要前端依赖：

```powershell
python -X utf8 .opencode/skills/term-extract/scripts/memory_ui.py
```

默认地址为 `http://127.0.0.1:8765/`。保持服务进程运行，Ctrl+C 停止。可指定端口或只读查看：

```powershell
python -X utf8 .opencode/skills/term-extract/scripts/memory_ui.py --port 8766
python -X utf8 .opencode/skills/term-extract/scripts/memory_ui.py --read-only
```

从其他目录启动时传 `--project-root 'D:\你的目录\extract_skill_1015'`。默认私有库位于项目 `.term-memory/`；如果 OpenCode 设置了 `TERM_EXTRACT_MEMORY_DIR`，网页服务也要使用同一设置。页面会显示实际项目和存储位置。

服务只监听本机回环地址，无账号系统。答复人姓名用于审计，不是身份认证。写接口检查来源和会话令牌；只读模式禁止全部写操作。普通 GET 查询不建库；可写服务的后台维护可能保存冲突扫描结果。

## 六个入口

| 入口 | 用途 |
|---|---|
| 学习与案例 | 查看 OpenCode 学习记录、可信案例与旧版流程历史；提供可复制的 OpenCode 提示词 |
| 待确认事项 | 回答局部语义差异和疑似经验冲突，查看已答复记录 |
| 经验库 | 阅读规则、适用范围、来源、修订和当前生效版本 |
| 运行与反馈 | 追溯不可变运行、用户原话、修正稿和证据 |
| 固定业务口径 | 阅读当前业务规则与真实 Git 历史差异 |
| 更新历史 | 核对修订、确认、评测、发布与撤回事件 |

## 从 OpenCode 发起抽取或学习

在项目根目录启动：

```powershell
opencode --agent term-extractor
```

项目默认代理同样是 `term-extractor`，因此也可以直接执行 `opencode`。模型由 OpenCode 当前会话选择与配置，网页不保存另一套模型配置。

纯抽取可以这样发起：

```text
请使用 term-extract 技能抽取以下文件：
输入：D:\path\input.json
请自主完成读取、抽取、校验与提交，并记录有证据支持的观察。
```

标签学习可以这样发起：

```text
请使用 term-extract 技能进行标签学习：
输入：D:\path\input.json
正确标签：D:\path\labels.json
案例族：项目或模板名称
标签已按当前业务口径确认。
请先隔离盲抽并冻结结果，再比较标签、归纳经验并验证。
```

“学习与案例 → OpenCode 使用指引”提供同样的可复制提示词。复制只写入剪贴板，不会自动向模型发送任何内容。替换为本机实际路径后再粘贴到 OpenCode。

纯抽取没有正确标签，自检产生的观察不能直接当作正确答案；标签学习先完成隔离盲抽与结果冻结，再对照标签。网页展示这些步骤的已存记录，不负责决定下一次工具调用。

## 导入可信验证案例

“学习与案例 → 可信案例 → 导入案例”填写本机输入路径、标签路径、案例族和用途。

- 输入与标签必须使用同一套 Cxx，标签已经按当前口径确认。
- 同一模板、项目变体、译文和近重复文档应使用同一案例族。
- 学习案例用于归纳；独立回归检查已有能力；保留测试不参与自动归纳和经验晋级。

路径指网页服务所在电脑上的文件，不是浏览器上传。导入只验证、归档数据，不进行抽取，不启动后台模型。可信标签不要求再重复人工确认每篇结果，但程序无法自动证明业务标签本身正确。

导入后，回到 OpenCode 请求继续对应的学习记录。网页不会替代理调度或启动旧版任务。

每条经验的原生验证至少需要 development、regression、counterexample 三种实验角色。后两者通常都以 regression 用途导入，再由 Agent 根据候选选择角色；回归和反例须来自两个独立家族，并与候选全部开发来源独立。同一原文不能在本次同时扮演回归和反例。反例不是随便一篇无关标书，而是会触及该规则适用或排除边界的案例。

推荐按真实的漏产品、关键参数遗漏、参数污染、数量和关系风险准备案例；保留测试 holdout 不参加归纳和晋级。数据规模建议、目录和原生验证提示词见[评测指南](evaluation-guide.md)。

## 查看学习结果与下一步

学习记录展示当前状态、关联运行、比较摘要、经验候选、待确认事项及下一步。详细结果可在关联“运行与反馈”查看。候选保存、验证完成和正式发布是不同事件，“有候选”不代表已经生效。

如果记录提示需要案例，导入符合口径且独立的案例后，回 OpenCode 继续；提示需要人工判断时，在待确认事项中答复后，再回 OpenCode 继续。不要在另一条会话直接把正确标签交给负责盲抽的代理。

“历史流程”保存旧版 Python 编排任务的结果、用量、比较与事件。此页无启动或继续按钮；即使直接请求旧 HTTP 创建、启动或模型设置接口，也会明确拒绝。

## 回答待确认事项

每项显示问题、局部原文或经验上下文、可选意见与作用范围。明确的漏产品、多产品、错误数量和错误串联不能通过选择“无害”覆盖。

你可以在网页选择处理意见并补充理由，也可以在 OpenCode 明确回复某一 `review_id`。对话工具将真实用户原话、选项和消息引用写入同一待办；代理不能代替你答复。处理一次即可，网页和对话不会形成两套审核状态。

答复只作用于指定案例或经验版本，不隐式确认整篇结果、批准所有候选或修改全局业务规则。已答复记录保留不可覆盖。保存后回到 OpenCode，让代理读取答复并继续相应流程。

新增候选会检查冲突。可写服务运行时，后台每 60 秒检查是否需要扫描：候选或业务口径变化时重扫，否则默认七天一次；服务关闭期间不执行。也可点击“检查经验冲突”立即扫描。维护只记录疑点与待办，不调用模型，不自动修改发布集合。

禁用后台维护：

```powershell
python -X utf8 .opencode/skills/term-extract/scripts/memory_ui.py --no-maintenance
```

`--read-only` 同样不启动维护。

## 维护经验和旧来源

如果 v1 已发布、v2 是候选，页面分别展示当前生效 v1 和最新 v2。新修订尚未发布时不影响 v1；编辑创建新 revision，历史不覆盖，并发修改会要求刷新。

### 人工审核后直接发布

1. 打开“经验库”，选择候选或希望审核的最新修订，查看规则正文、触发词、适用/排除条件及来源证据。
2. 如需修改，先保存新 revision，再核对新内容。点击“人工审核发布此版本”。
3. 填写审核人和审核理由，提交对这一个 revision 的批准。页面绑定修订和内容摘要；审核期间内容变化会要求刷新重新核对。

此操作**无需先评测，也无需先确认来源整篇抽取正确**。来源未确认、反馈缺少完整修正稿或整篇曾被纠错时会提示你，便于判断规则证据；源文件缺失、摘要变化或仍有未解决的阻塞冲突时不能发布，应先处理。人工审核不建立可信标签，不自动执行来源确认，不会把模型整理稿升级为人工答案。

发布依据显示为“人工审核发布”，保留审核人、理由、时间、修订和独立审核记录。没有评测记录时明确显示“未评测”；已有报告但此次没有采用评测准入时显示“未采用评测准入”。人工发布不会生成或改写 passed 报告。需要时可以后来补做验证。

Agent 自动发布仍须通过独立试验门槛。主代理没有人工发布工具，不能通过对话自行代填审核人或调用网页接口代审。人工 CLI 也可执行同一操作，命令见[经验维护说明](../.opencode/skills/term-extract/references/experience.md)。

网页保留候选修订、旧来源确认、补完整反馈稿、旧离线评测、评测后发布和撤回。人工直发与评测后发布分开显示、分别记录依据。这些是记忆维护操作；旧离线评测只检查给定输出与断言，不运行模型。日常抽取、学习和真实模型对比验证统一在 OpenCode 完成。

### “离线评测清单 JSON 路径”填什么

填入服务电脑上 **manifest 清单文件的绝对路径**。不是标书原文 JSON，也不是完整七字段 `labels.json`。manifest 引用已注册的索引、已经生成的 baseline / candidate 两组结果和 required / forbidden 等关键标签断言。点击评测只读取和比较这些文件，不会自动调用 OpenCode 或模型生成结果。

日常推荐路线无需填写这个框：导入原文和可信标签，让 OpenCode 自主选择相关案例、运行独立 baseline / candidate 子会话、比较并发布。需要验证一条候选经验时，比较条件固定为同一模型、口径和正式经验基线，只有本条候选注入与否发生变化。

想了解旧清单结构或试按钮，可以运行[隔离合成示例](../examples/evaluation/README.md)。准备脚本打印演示库、候选编号、manifest 路径和隔离网页命令；将打印的 `manifest_path` 填到**演示网页**中该候选的路径框。手写示例输出只用于演示报告，不是模型成绩，也不应套到真实候选上。

离线断言覆盖多少业务要求，报告就只能证明这些要求；只写一个 AP 的断言不能证明整篇没有漏交换机。完整准备步骤与能力边界见[评测指南](evaluation-guide.md)，详细旧清单字段见[清单参考](../.opencode/skills/term-extract/references/memory-evaluation.md)。

旧反馈只有用户原话时，可以补完整七字段 JSON 修正稿；系统保留旧运行和原话，创建新的带稿反馈。不要把尚未核验的模型整理稿当作用户正确标签。已有确认的整篇正确标签也可直接作为可信案例导入。

撤回移除当前发布指针，保留来源、规则、实验、人工审核和审计，不自动恢复旧版。后续新抽取不再使用被撤回经验；已准备任务保留原快照。恢复时可重新人工审核发布，或针对当前集合重新验证后发布，不能复用旧审核动作或已消费报告冒充新的发布。

## 怎样感知经验变化

- 学习记录说明产生了哪些候选、仍缺什么证据。
- 待确认事项说明需要你判断什么，并保留答复原话。
- 经验库展示规则正文、来源、修订差异、当前生效版本和发布依据；人工审核与评测准入有明确区分。
- 固定业务口径展示技能文件的真实 Git 变化；它与经验候选不是同一个层级。
- 新发布经验用于之后新准备任务；已在执行的任务继续使用冻结快照，交付记录可核对具体版本。

模型收到经验不代表采用；发布也不代表每篇都能召回。没有记录的 token 或费用显示为未记录，不能解释成零成本。

## 技术边界

```text
OpenCode term-extractor
  → 自主读取、抽取、校验、提交、对照和验证工具
  → agent_learning / memory_learning / evolution_store / memory_store
  → 同一私有 SQLite 与不可变工件
                          ↑
浏览器 → 本机 HTTP → 查看记录、案例管理、待办答复、经验维护
```

页面采用原生 HTML、JavaScript 和 CSS，无 CDN、外部字体或构建步骤。它只做本地查询和管理写入，不保留可触发模型的 HTTP 执行接口。旧任务模块为兼容历史数据而保留，不是网页执行入口。

局部证据摘录可能截断，会明确提示。当前没有多用户认证、完整语义冲突识别或向量检索；程序不能自动证明全部标签可靠、所有案例族独立，也不能凭合成软件测试证明真实标书质量。

私有数据库、文档、标签和运行工件均被 Git 忽略，推送代码不会携带它们。

# 两种运行模式（0.5.0）

## 纯条款抽取

输入只有标书。OpenCode 先完成抽取，按原文核对漏产品、参数覆盖、混入、数量与关系，并留下最多三条有标签证据的可迁移观察。结构校验通过、自检通过和生成观察都不代表已有正确标签。

用 term_learning_create 的 extract 模式可以自动执行并尝试用已有可信案例验证候选；没有验证案例时保留候选，状态说明等待案例。也保留普通 prepare/read/checkpoint/validate/commit 的交互抽取入口。

## 标签学习

用户提供输入、人工确认的正确标签、案例族。标签使用输入同套 Cxx。高层工具接收路径，不读取标签正文给当前抽取会话。运行器在临时隔离项目启动全新 OpenCode worker，禁用文件、网络、命令及任务工具，只交付完整原文、固定口径和短经验包。

预测冻结后，服务才读取标签进行对照。对照忽略产品分类和 ID 重排，比较采购对象、有效参数范围、general/separate 关系与数量。定位不同不直接等于参数漏抽；仅将相关差异邻域交给局部判断。无法可靠判定的差异进入待办，不能默认为正确。局部判断不能覆盖确定的漏产品、多产品、错误数量或错误串联。

从已判定的错误或正确处理方式归纳候选，记录适用、排除、证据标签和来源。先合并重复经验，再检查可能冲突。纯品牌 general、已排除布线和机柜的旧经验会被提醒复核，关键词冲突提示本身不等于已证明矛盾。

## 自动验证与生效

运行器选取学习案例与不同案例族的独立回归/反例；使用同一模型与业务口径分别执行已发布基线、加入候选后的抽取。验证调用不产生新经验，保留测试不进入归纳过程。记录实际会话事件、预测文件和哈希；不得手写“模型已抽取”的报告。

自动晋级要求目标通过、没有回归错误、独立回归及反例通过；除归纳来源外，回归和反例至少来自两个独立案例族。仅保留正确行为的经验可以证明本次验证未退化，但不能称作已经提高准确率。标签案例不足、比较歧义、预算不足或可能冲突时保留候选并给出下一步。新发布经验供新任务建立快照；当前任务的已交付经验不切换版本。每项验证实验单独固定其启动时的正式基线，多条候选依次发布时，后续实验使用新的基线。

## 人工入口

默认通过工作台的“待确认事项”答复；也可在对话中明确答复某个待办，由 term_learning_reply 保存到同一记录，保留用户原话。局部答案只作用于指定案例或经验，不隐式确认整篇、批准所有经验或修改全局口径。答复后继续原任务；新增可信回归案例后也可继续等待案例的任务。

运行前在“模型设置”选择本机 OpenCode 已配置的 provider/model，控制调用次数、时间和单次提示字节预算。页面不保存密钥。完整数据流、文件和存储说明见 [方案说明](../../../../docs/learning-evolution.md)。
